# Administrator cloud synchronization

Local inventory remains an offline JSON document. Opening an older file performs a pure v1–v6 migration in memory; the first save writes a recoverable sibling `.backup-...json` containing the original bytes. v7 adds a stable UUID, unlisted-by-default products and separate CAD storefront prices. Future schema versions are rejected. CSV and XLSX retain existing fields and append the public shop fields.

Open the cloud panel, log in with the existing administrator account, and complete the first-password-change form if required. Login alone sends no inventory. **Connect and upload current inventory** authorizes autosync for that exact file and account. **Download and connect** saves the selected cloud book to a chosen local file, backing up an existing destination. A copied JSON `cloudLink` does not authorize upload.

The fixed service is `https://api.amaneacg.space` since v0.2.2. Since v0.2.3 the separate fixed request Origin is `https://console.amaneacg.space`, matching the migrated server's `ADMIN_PUBLIC_ORIGIN`; it must not be inferred from the API transport origin. All administrator requests and authenticated images pass through Electron main; redirects and arbitrary endpoints are rejected. Session and CSRF cookies are main-process memory only, with an origin-bound encrypted token file in Electron userData when OS safeStorage is available. The old GCP session is not reused; log in once when upgrading from v0.2.1 or older. v0.2.3 retains v0.2.2 credentials and pending requests. Passwords are never saved. `basic_text` storage is refused; unavailable encryption uses session memory only. IPC checks the app window, exact main frame and renderer URL, with sandbox/context isolation and blocked external navigation.

Sync keeps one job in flight. `stock-sync-journal.json` in userData stores account/file/book binding, acknowledged version/hash and the exact pending request body/key/version **before transmission**. This journal contains private inventory snapshots but no passwords/session/CSRF secrets. Retain it for recovery; do not publish it. Lost responses, 5xx and network errors replay identical bytes after retry/restart. Definitive 400/413 validation rejections allow corrected local content to receive a new request key. New local edits during upload survive and queue another snapshot. Downloads re-check the local hash inside the serialized file-write callback. Each remote replacement creates a sibling backup.

A 409 conflict stops automatic writes. **Use local to overwrite cloud** (v0.2.4) requires confirmation, reads and backs up the latest remote snapshot beside the local file, then sends a versioned PUT to the same inventory ID. Another concurrent remote change requires a new choice; this operation never recreates a deleted book. **Back up local and use cloud** preserves local bytes before replacement. **Back up and upload as a new inventory** allocates a fresh UUID and preserves the original cloud book. Renames preserve IDs and the exact pending request while moving the file binding. Switching accounts pauses the old job; logging back into the original account restores its pending request. Logout clears local credentials even when network revocation fails, and reports that server revocation was not confirmed.

Since v0.2.1, an explicit stock API 404/410 automatically recreates an already connected missing cloud inventory. A failed write or create conflict first checks the current cloud record: an active record remains a conflict, including a historical request tombstone for an ID that now exists again. Generic router/proxy errors, unreadable responses, authentication/permission failures and network loss never authorize recreation. A persisted `replacement` intent names the new UUID before the local file is backed up and rebound; journal lookup accepts either side of that exact account/path transition after a crash. The new POST then uses a durable snapshot/key before every attempt. Repeated retries replay those bytes, and edits made during upload follow in a versioned PUT. Recovery is bounded to one new identity per sync run.

Recreation preserves the local name, items, listing choices and transaction history. The deleted cloud record and its historical references are retained. Independent cloud shop registration/edits belong to the old product records and are not migrated; the new inventory projects its current local product data under new product IDs.

Listing is separate from stock and cost. Public CAD original/current price and discount basis points never perform currency conversion. Since v0.2.2, explicit CAD card sale edits update shop pricing, and shop price edits update the CAD card sale. Registered shop prices use a durable second phase after stock synchronization; product conflicts have separate resolution controls. See [price synchronization](SHOP-PRICE-SYNC.md).

Since v0.2.4, dedicated durable operations save listing and owned images for both registered and unregistered linked products. Batch listing accepts at most 200 currently visible selected items and registers products on first listing. Uploading a cropped image creates a draft; saving it is a separate image-only operation. Registered names and categories stay under shop management; ordinary inventory snapshots preserve registered images and listing instead of overwriting them. New controls require both inventory and product permissions plus the server capability marker; the Mac API and admin deployment must land before they activate. Unknown operation results retain the exact request across restart and must be resolved before choosing a different inventory copy. See [shop connectivity](SHOP-CONNECTIVITY.md). Product-lookup images remain separate from owned shop images.

Verification uses synthetic in-memory documents and temporary test directories only; no real local inventory is uploaded. `npm test` covers lost responses/restart, concurrent edits, conflict/backup, failures, account switching/relogin, encryption fallback, sender checks and schema migration. `npm run build` checks production main/preload/renderer compilation. These checks do not establish live-account sync or native runtime acceptance. Packaging and GitHub publication are separate release steps; v0.1.16 assets must remain intact.

Electron API reference: https://www.electronjs.org/docs/latest/api/safe-storage

## Native smoke evidence (2026-09-07)

`scripts/smoke-cloud.cjs` runs real hidden Electron with temporary synthetic userData and intercepted `fetch`. Passed: sandboxed preload/context isolation, renderer login form, zero inventory uploads on login, explicit connection, listing autosync, cloud selector, denial of a second native window's IPC calls, logout and an acknowledged durable journal. All requests in this smoke were in-process test responses. The process exited with code 0 and no smoke process remained. Hidden `capturePage` did not provide a display surface within 2 seconds; there is no screenshot or visual-quality acceptance from this check.
