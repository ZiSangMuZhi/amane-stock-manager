# 库存与商店联动（0.2.4）

## 桌面操作

在商品列表点击“批量上架 / 下架”，选择当前筛选结果内的商品（每次最多 200 件），确认后提交。过滤隐藏的选择会自动移除，切换文件会清空选择。批量上架将尚未注册的商品一并注册，保持商品分类和价格；下架不删除库存或历史订单。

单品上架开关与批量操作使用相同服务端接口。主图编辑先上传裁切图，再点击“保存主图”；移除主图也需要保存。主图、上架请求不含价格字段，不会提交价格表单中的草稿。商品主图有外部修改时，需要明确重新载入或保留草稿后保存。

这两项操作要求已登录并连接当前库存，具备库存及商品管理权限（兼容旧内容管理权限）。不要求定价权限，但如果库存另有待发价格修改，须先完成或处理该价格同步。

## 能力与接口

新的服务端库存响应携带 `shopOperationsSupported: true`。缺失时禁用新操作，并保留现有同步、改价与冲突处理。服务端部署后重新同步即可更新能力状态。

配套网站代码位于 `ZiSangMuZhi/amane-acg-platform` 的 `work/stock-shop-connectivity-20260924` 分支，提交 `ac6f9e6a23a617983b32143db59525ce260e4b23`。由 Mac 端按该分支的 `admin-platform/docs/STOCK-SHOP-CONNECTIVITY-MAC-HANDOFF-2026-09-24.md` 合入当前生产基线并部署；历史主图/上架差异需先预览、备份再回填。Windows 发布桌面程序不代表网站已部署。

请求使用现有 `POST /api/stock-books/:id/operations`，请求体仍包含 `version`、`requestKey` 和 `operation`：

```json
{"type":"shop-listing-batch","barcodes":["SKU-1","SKU-2"],"listed":true}
```

```json
{"type":"shop-image","barcode":"SKU-1","imageId":null}
```

`imageId` 为已上传且完成方形裁切的商品媒体 ID，或表示移除的 `null`。普通库存快照不能覆盖已注册商品的主图与上架状态，必须使用明确的商店操作。新网站服务端在商店编辑主图或上架状态时同步更新来源库存版本，桌面按原有版本机制接收变更。

## 恢复与冲突

`stock-sync-journal.json` 的 `shopOperationPending` 保存完整请求字节、请求键、版本和操作前相关字段。结果未确认时，后续库存请求不能越过它；重启后也重试原请求。明确的拒绝不会误触发新建库存。响应成功后先合并本地文件，再确认恢复记录；期间发生的其他本地编辑继续保留。

库存冲突新增 `use-local`：读取最新云端版本，备份云端原始库存，保存新请求后，以同一库存 ID 发出版本受控的 PUT。再次冲突需要重新选择；删除或失踪的云库存不会因该选项而自动建立新 ID。已注册商品的主图、上架状态仍遵循独立商店操作规则。

备份和同步日志含内部库存资料，仅保存在用户本机；不纳入安装包或 Git 仓库。
