# 商店价格同步（0.2.2）

## 价格操作

| 操作 | 结果 |
| --- | --- |
| 编辑卡片 CAD 售价 | 更新商店现价；保留已有原价，现价超过原价时提高原价；重新计算折扣 |
| 编辑商店原价、现价或折扣 | 按整数 CAD 分和折扣基点计算；卡片币种为 CAD 时更新卡片售价 |
| 只编辑进价、数量、名称或图片 | 不创建已注册商品的价格写入 |
| 编辑非 CAD 售价或切换币种 | 不进行换汇，不自动更改商店价格 |
| 清空售价 | 不将商店价格改成零；免费商品必须明确填写 0 |

价格表单保留尚未保存的文本。只刷新库存数量不会覆盖草稿；真实外部改价会提示冲突，需要明确采用新值或保留草稿后再保存。保存反馈表示本地已保存，云端面板负责显示最终同步结果。

## 同步协议

此版本兼容网站 `work/mac-self-host-setup` 分支的 `82367c2` 接口，无需服务端迁移或部署：

1. 为已有库存准备新快照时，获取当前云端库存，验证库存版本，并比较新旧 `item.shop` 价格字段。只针对实际价格变化查找已注册的 `sourceBookId + sourceBarcode` 商品。
2. 将目标价格及当时的商店基准价格与库存待发快照一起写入 `stock-sync-journal.json`。库存 PUT 沿用原有版本检查和幂等键。
3. 库存确认后，持久保存待发商店价格。读取商品最新版本，允许库存数量导致的版本增加；若商店价格有不同修改，停止并提示价格冲突。
4. 以最新名称和图片组合价格请求，省略 `categoryId` 以保留服务端权威分类。保存完整 PUT 字节、版本和幂等键后再发送。商品接口本身不会更改上架状态或数量。
5. 只有价格队列也确认完成后，面板才能显示“已同步”。网络错误和响应丢失重放原请求；409 不会自动获取新版本强行覆盖。

价格冲突和库存版本冲突分开处理。用户可明确重新应用待发价格，或采用商店价格。采用商店价格只替换仍等于待发值的本地价格，不覆盖同步期间产生的新编辑；随后按普通库存同步保存。

`GET /api/products`、`GET /api/products/:id` 和 `PUT /api/products/:id` 使用网站已有权限与审计。已注册商品价格写入需要 `content.manage`、`products.manage`、`pricing.manage`。普通库存进价不公开。新订单读取新价，已有订单快照保持原值。

## 迁移与恢复

- 固定服务地址为 `https://api.amaneacg.space`，禁止从库存文件或 renderer 传入任意目标地址。
- 新登录凭据使用独立、带 origin 的加密存储；旧 GCP cookie 不发送至新服务，首次升级需重新登录。
- 库存 schema 不变。同步日志继续绑定账号、文件路径和库存 ID。离线修改、退出登录和换文件不会把待发数据交给另一个账号。
- 保留原有云库存删除后的自动备份、重建逻辑。旧商品的待发价不转交给新库存 ID。
- 不删除同步日志来“修复”问题；它包含恢复所需的原请求。日志是私有资料，不应提交 Git 或公开发布。
